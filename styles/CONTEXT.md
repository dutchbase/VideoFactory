# Style recipes

Read `_shared/permissions.md` before editing a shared style. You need `style:<id>` permission to change it. A video scope can use a style but cannot edit it. Pause for human review only at the style stages required by the active session permission.

Style families live in `styles/_families/<id>/family.md`. A family record points to the real guide, runtime, template and any example video. The built-in family is Modern (`styles/_families/modern/family.md`, guide `_shared/modern.md`). No finished Modern sample video is registered yet. Start a family contract from `_templates/style-family/`.

Run `.venv/bin/python anim.py catalog import` to add each family's default variant if it is missing. Import is idempotent and keeps existing style files. Imported variants have `origin: "existing-reference"` and `readiness: "needs-review"`. The import does not approve them or create rendered samples.

Each `styles/<id>/` owns an authored `style.md`, linked material IDs in `materials.md`, and optionally a `template/` in the scene/runtime format. Start custom variants from `_templates/style/` (guided: `/vf-new-style`). `base_kit` stays present for existing callers: copy the template's value. The added fields `family_id`, `renderer`, `supported_formats`, `origin`, `reference_videos`, `references` and `readiness` describe provenance and available evidence. Readiness is not an approval. A sample preview is real only when the template contains an authored HTML preview.

The same `style.md` frontmatter holds the editable setting and visual recipe fields: `setting`, `environment`, `components` (a list of short scene descriptions), `captions`, `voice_guidance`, `motion_guidance` and `visual_instructions`. `supported_formats` declares wide or tall. A format has sample evidence only after a rendered MP4 and a matching `sample.json` prove 12 seconds (11.95–12.05), 24 fps, exactly 288 frames, correct dimensions and changing decoded frames. The manifest also binds the exact authored scene, runtime, local resources and materials revision. Changing any source needs a new render. A style needs an authored `template/<format>/index.html` scene that uses the player time API (`_shared/modern.md`) before `prepare_style_sample` can render it. An HTML file by itself is a draft, not a sample.

`studio.references.plan_style_materials(root, style_id)` exposes the supplied, OpenAI and licensed-stock routes. `request_style_materials` requires the plan's `input_revision` as `expected_revision` and saves an agent handoff against that exact style-material fingerprint. Public website extraction uses `inspect_website` in contained Chromium. It saves an original screenshot and the computed palette, fonts, components and logo candidates under `02_assets/website/`. Each HTTP(S) resource is fetched through a validated, DNS-pinned connection, including redirects. Page JavaScript, service workers, WebSockets and non-GET requests are blocked. Computed evidence reflects the static page and CSS, so pages built by script may give sparse evidence. The input revision is captured before browsing and checked before saving. `save_website_reference` accepts only bounded public evidence, and logo candidates with unknown rights stay references. Source edits stale the materials and sample reviews. Linked materials keep description, source and rights in `library/materials/<id>/material.md`.

Sample imagery requires an exact positive `rights` value: a licence in `libcore.ALLOWED`, or `User supplied`. `OpenAI generated` also requires a completed OpenAI generation record that matches the style, file path and SHA-256. Free-text permission claims and website logos with unknown rights are never selected. A failed rerender keeps the previous sample pair. Registration checks the current materials and source hashes under the workspace lock.

The local API mirrors these helpers at `GET /api/creative/style/<id>/materials-plan`, `POST .../materials-request` and `POST .../website-reference` (validated evidence plus `expected_revision`). `POST .../sample/<wide|tall>` accepts the materials `expected_revision`, renders synchronously and may take minutes. Duplicate calls return busy. `GET .../sample/<wide|tall>` reports `rendering`, `rendered` or `missing`, so the dashboard can poll while a POST is pending. These routes use the normal Studio write token for POSTs. Only the agent runs `inspect_website`. The server does not execute website JavaScript or shell instructions supplied by a client.

Selecting a style copies the recipe and template into `videos/<brand>/<slug>/style/` with a `snapshot.json` that holds the source revision and the copied file hashes. Shared edits do not change a video's snapshot. Propose an update in Studio, inspect the file changes, and confirm it only when the local snapshot files still match their recorded hashes. Then review the affected scene and export again.

You check the recipe, the rights of linked material and a working sample before you use the style. Do not present an absent template as complete.

# Local Studio

Start the Studio with `.venv/bin/python anim.py studio`. It serves `http://127.0.0.1:8765/`. Use `--port` for a second server, for example a test server on 8799. Run one server for each port. After you change Studio Python code, restart the server. A restart stops a running Studio agent, and its request is marked failed. Review pages have stable paths: `/videos/<brand>/<slug>/review/<gate>`. The server binds only to loopback. `studio/web/` is the user interface. `workspace.py` reads and edits authored files, `jobs.py` runs guarded production actions, and `server.py` serves the API, media and trusted previews.

Input: existing `videos/`, `_shared/`, `library/`, `styles/` and the stage contracts. Output: authored edits and review events in those shelves, and `.studio/` for local jobs, logs, requests and the workspace lock. Files stay the source of truth. The per-run write token protects browser writes. It is not a shareable account credential. No publishing route exists.

The browser starts with `/api/bootstrap?view=shell` (token, jobs, requests). Video lists and selected project metadata use `view=summary` or `view=shell`. These omit full review checks and history. Overview reviews show the recorded decision marked as unchecked until you open the exact review. Recorded states help navigation and never authorize a decision. Default API responses still include their original full detail. Summary lists and the shared material and file inventory use a process cache bounded to 128 entries and five seconds. Studio writes invalidate that workspace's entries, and external edits appear after expiry. Detail checks, saves, decisions and production validation bypass the overview cache.

Library requests use `/api/materials?view=summary` and `/api/materials/files?view=summary`, with `q`, exact `kind`, `offset` and `limit` (48 by default, at most 100). Both return `items`, `total`, `offset`, `limit` and `kinds`. `/api/materials/item?id=...` opens one record without a file walk. `ids=a,b` retrieves only linked records and keeps individual missing-record errors. The file picker loads when you open its disclosure. Navigating cancels old reads. Writes continue independently. Background sections update their own DOM and offer a local retry, keeping editors and drafts intact.

The dashboard requires a brand selection with no preselected brand. The CLI also requires `anim.py new <slug> --brand <id>`. Add `--engine hyperframes` for that engine. Use `_shared/dashboard-review.md` for the agent handoff. You check the exact saved revision at every gate. A running or successful job is separate from approval. A failed or cancelled job leaves partial outputs incomplete: rerun only after you review its log and inputs. Voice generation requires an explicit paid confirmation of the current script (`_shared/voice.md`).

For a creative request, read its `subject` and `input_revision` in `/api/requests`. Then read `styles/CONTEXT.md` or `characters/CONTEXT.md` and the subject's current stage `CONTEXT.md`. The active stage is the first unapproved gate at `/api/creative/<type>/<id>`. Style: `brief → materials → sample`. Character: `brief → design → identity → animation:<variant>:<action>`. `/settings` shows the same handoff in the dashboard. Codex and Claude claim a waiting request with `anim.py studio-request <id> --claim <agent>`. They do the actual work, save complete question-form answers and an editable brief, mark the exact fingerprint ready, open or post its `/creative/<type>/<id>/review/<gate>` link, then wait for your decision. If no browser tool is available, post the link and say that opening was unavailable. No daemon claims a request on its own. You can start one from a review page. **Run agent** has the Studio claim the request and run `claude -p` unattended in the workspace (`studio/agent_runs.py`; script, cues and scene requests only; log in `.studio/requests/<id>.log`; **Stop agent** cancels it). **Guide me** opens a terminal with an interactive `claude` that claims the request itself and walks you through the choices.

The Studio API exposes generation prepare, list, detail, batch approve, run and native output registration at `/api/generations`. The batch page shows the exact prompt, count, route, references and context before approval. A completed batch is still draft creative evidence. Character candidate, identity and variant registries have dedicated routes. Pack source is editable, and generated frame indexes are read-only. A video's creative selection proposes changes before apply and protects local snapshot edits. A renderer mismatch, or an absent authored renderer engine, blocks creation or apply. `/api/files` keeps revisions for editable source. No Studio route publishes.

Native character projects use a separate review path. `calibration/native/` is working source. Register a complete, hashed `manifest.json` and `rig-review.json` through `POST /api/characters/<id>/variants/<variant>/native/candidate` with the exact variant and manifest hashes. A replacement also needs the current candidate manifest hash and `confirm_replace`. Prior candidates move to `native-history/`. The `rig:<variant>` gate reads `native-candidate/` and requires both views, A–H/X mouth metadata and six distinct hashed images per view. Approval permits `native/activate`, which atomically installs the reviewed source and keeps prior native renders. Only registered action and expression SIF bindings can enter `native/render`. That request returns a Studio job ID and uses the existing write token, lock, logs and cancel route. The manifest, the actual Synfig and FFmpeg binaries, the compositor code and the selection key the validated RGBA frame cache. A checkerboard MP4 from those frames is a dashboard preview. Changed source leaves a prior clip visibly labelled until its replacement succeeds. Once activated, the character page opens the native clip panel instead of the canvas playground. An invalid active manifest still shows the last validated clip for repair. Canvas action approval stays current during candidate review. After activation, each native action gate requires current clips in both views and its own decision. No candidate and no successful job grants approval. Pilot measurements: `studio/native_pilot/STATUS.md`.

Changing an approved character brief or selected concept can stale downstream registries. Complete a fresh approved-input OpenAI batch, then use the explicit replacement check on the character page. Its current registry hash prevents overwriting a newer selection. Prior art and review history remain, and each new revision returns to human review. A creative video snapshot freezes shared resources found in authored scene HTML, JS and CSS, and serves local source with URLs rewritten to its own copies. New shared dependencies require reapplying the snapshot. A browser load from an installed scene cannot silently fetch shared fallback bytes.

Check the interface at desktop and narrow widths in a contained headless browser (Playwright Chromium). Reproduce these cases in a disposable video: type an unsaved script while jobs poll; edit that file externally and observe a retained draft conflict; put `<script>` text in a title and confirm it renders as text; reach Save and Approve by keyboard at narrow width; and inspect the silent fixture's voice step as not applicable. Check media seeking, deep-link reload, back and forward, empty collections and failure messages. Do not drive your real desktop. Measured performance and how to repeat it: `studio/PERFORMANCE.md`. Visual design: `DESIGN.md`.

Managed runs save settings before production (`_shared/autonomous-runs.md`). Studio jobs and managed CLI runs share one production lock. Automatic validation never becomes your approval. Local script guidance is `_shared/script-production.md`.
